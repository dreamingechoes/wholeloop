# 0113 — Owned foreground routes and native recovery

- **Status:** Accepted
- **Date:** 2026-10-26

## Context

A queue of worker claims is not a complete product route. A foreground controller must preserve its original authority, finite budget and stage/effect identities after interruption. A lost parent process cannot make an orphaned native client safe to repeat. Existing gate snapshots include HEAD, so committing after QA would immediately invalidate their basis.

## Decision

Use additive runner event/facet families in the shared authoritative delivery journal. Keep bounded immutable request sidecars and stable keys outside repositories. Bind an original private grant to one runner run; a recurring grant must separately admit independent runs. Claim one exact controller generation, retain unknown ownership and journal stage intent before native input.

Derive mandatory routes from the accepted plan: pin acceptance definitions before builders; allocate owned workspaces; review build plans; implement and commit only on owned topics; verify/review those exact committed candidates; validate the complete milestone and requested endpoint. A topic commit establishes a candidate, not passing QA or publication. Research and initial definition retain their own bounded host/derived-plan contracts. Existing supervised commands and public v1 envelopes keep their meanings.

Use a fixed private native wrapper that retains registration and nonce-bound cancellation after controller loss. Only the original live wrapper signals its own group. Drain output after a broken parent pipe and retain only typed outcome metadata; never persist unchecked native transcripts or credentials. A fresh controller observes exact registration/outcome/group absence. Missing semantic output remains missing even when process closure is known. Unknown invokers retain original queue reservations. Stop/pause/resume never reset budgets or remove work, and stale results cannot publish.

Control hosts, selected current input/decision proofs, endpoint evidence and recovery observations remain separate from worker claims. Fixture execution never certifies a model/client or hosted effect. Missing capabilities and non-delegable facts produce honest finite none-policy limitations, without a human prompt.

## Alternatives rejected

Stealing a heartbeat-expired claim cannot establish old process termination. Signalling a recorded PID risks another process. Blind stage replay duplicates effects. Killing the whole user session would exceed ownership. Raw transcript persistence can retain credentials. Treating a local topic commit as a verified delivery would bypass independent QA.

## Verification and implementation boundary

The first increment implements deterministic route/ownership replay, stable-key preparation, operator controls, immutable result/checkpoint recovery, exact native exit/output, parent death/broken pipes, private cancellation and unrelated-process preservation. The compiled CLI exposes schema, prepare, status, pause, resume and stop controls. It exposes no arbitrary command/result import and no complete-route run command yet. The internal controller requires a fixed trusted host; fixture hosts cannot certify an endpoint.

P6-10 remains in progress until a fixed domain host, owned foreground entrypoint and endpoint/reconciliation commands connect the existing services end to end. Live native containment, actual model execution and real hosted acceptance remain separate observations; version/help and configuration declarations cannot certify them. Tests and documentation must preserve this distinction.
