# 0123 — Owned native review rounds and recovery

- **Status:** Accepted
- **Date:** 2026-10-26

## Context

The delivery transport can produce an owned candidate and machine decisions, but a complete report is not a code review or a test suite. Reusing an unbound headless result would lose the original grant, native role proof, stage deadline and journal-selected receipt. Restart must recover the exact review round without resetting its budget or issuing another model call.

## Decision

Add fixed read-only gate workers over the existing native delivery transport, queue and gate engine. Inspect only the declared unit of the pinned round; refute only its actual recorded finding with a bounded verifier number. Scope each fresh reviewer/verifier/refuter assignment, structured report, input pack and original process owner before input. Typed controller task metadata narrows the purpose without changing role tools or old assignment schemas. Select private context after claim so assignment audiences can bind the actual attempt; validate its hashes, role, references and total limits before copying.

Require the current committed file bytes and index as well as the original private HEAD receipt. Pin the actual review input/rubric to the accepted plan guidance and unchanged candidate. Decode exactly one captured report into the unchanged gate result/vote contract. Reject worker process-execution claims, suite units, unscoped outputs, extra outer claims, late results and fixture-only runtime authority. Only the controller's separate QA host can execute suites and observe behavior.

Use semantic identity for reconstructed controller objects and keep actual UTF-8 resume/artifact byte hashes separately. A restart may reorder JSON keys without changing any input value; it must neither invalidate the original report nor normalize away changed code bytes. Preserve the reproduced paused-recovery failure and its byte checks.

Connect review rounds to original root stages through private consumed markers, stable machine-review subject locators and exact round bindings. Keep the existing round engine, quorum, recorded findings and failed budgets. No legacy owner approval or existing item completion is fabricated. A fresh read-only observer can validate original native receipts and seal a lost final metadata write only after every required inspection and submitted vote is observed, unchanged and positively closed. The existing strict-majority and fail-safe unanimity rules decide the result; an unavailable refuter is neither a fabricated vote nor a new quorum requirement. It never launches another model, suite or repair. Cancellation uses original private nonce channels, including after revocation.

The handler supplies code-review evidence only. Behavioral QA, repair orchestration, integration, delegated acceptance, complete-route configuration and public execution/endpoint wiring remain P6-10 technical work. These new components do not close P6-10 or native/account acceptance.

## Alternatives rejected

A model saying tests passed cannot stand in for a suite process. A bare result file has no original native or grant binding. HEAD alone misses uncommitted bytes and index changes. Comparing serialized reconstructed objects confuses key order with changed input. Recreating a lost descriptor or review subject resets ownership/budgets. Resetting failed rounds or inventing human approval bypasses the existing gate policy. Increasing ordinary test deadlines to fit a complete multi-worker round hides its actual runtime requirements.
