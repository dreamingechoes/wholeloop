# 0041 — Challenged learning decisions and scope closure

- **Status:** Accepted
- **Date:** 2026-10-19

## Context

A merged scope is not a decided product outcome. Closing a parent after a manually
closed child can erase the learning step, while an iteration without evidence
restarts the same debate. A recorded keep/kill/unflag also cannot establish an
actual flag or code change that the workflow did not perform.

## Decision

- Pin the original promise and latest completed checkpoint's exact report/basis.
  Preserve unknown metrics, qualitative gaps and pending checkpoints. Standalone
  entry may use explicitly labelled self-reported observations with person and
  non-secret references; it invents no measurements or shipping history.
- Record the person's leaning, actual learn.decision guidance and effective
  profile. A challenger must oppose that exact plan, name an alternative and give
  argument/limits. All four coverage areas remain mandatory across profile tones;
  additional question budgets remain one/two/three. Changed observations or
  guidance/profile require explicit re-planning and a fresh counterargument.
- Require the actual person's outcome, written reason, latest challenge event and
  acknowledgment of every unknown or pending checkpoint. Keep/iterate/kill/unflag
  are immutable recorded choices. A model host stops before selecting an outcome.
- Iterate atomically records its choice and creates/reopens a linked framing
  draft. Include the complete framing structure and explicit owner questions for
  new validation, cost/priority and stop conditions. Start frame-problem without
  completing it. Reopen only an explicitly selected closed pre-spec idea without
  children; preserve developed initiatives and create a new linked idea instead.
- Keep/unflag propose flag cleanup. Kill proposes human disablement and removal
  work. No production flag, code, provider publication or Build is executed.
  Unflag requires an actual flag identity, rather than guessing a control.
- Canonical completion and scope/eligible-parent closure share one journal batch.
  Replay checks the decision receipt and prevents any initiative closure while a
  scope lacks a completed learning decision, including manually closed siblings.
  Reopening invalidates closure eligibility; reopen the parent before adding a
  new scope. Keep scope decisions recoverable before canonical completion without
  repeating their iteration creation.
- Store exact decision/argument/proposal projections and bounded resume refs
  outside repositories. Original checkpoint reports and prior idea history remain.

## Alternatives considered

| Option | Why not |
| --- | --- |
| Close scopes or initiatives at merge | Loses the explicit product outcome and learning evidence |
| Use a generic approved decision without an outcome/reason | Cannot distinguish keep, iteration, rejection and cleanup |
| Let profile intensity reduce evidence coverage | Makes a style preference change correctness guarantees |
| Treat iteration selection as a validated new idea | Invents validation and skips unresolved framing questions |
| Reopen a developed initiative and reuse old scope approvals | Blends old delivery history with a new hypothesis |
| Interpret kill/unflag as an actual flag change | Claims an external effect that never occurred |

## Consequences

The durable guard proves identity, coverage, human attribution and closure rules;
it does not prove counterargument quality, the truth of self-reports or causality.
Iteration framing stays draft work and cleanup stays proposed work. Real client
permissions, semantic challenge and physical interruption tests remain owner
verification; they do not block later local implementation.
