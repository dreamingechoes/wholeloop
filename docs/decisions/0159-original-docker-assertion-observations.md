- **Status:** Accepted
- **Date:** 2026-10-29

## Context

Recovering whole-product results must not replay tests or trust a stored host label and result status alone. The fixed Docker observer already journals the exact test effect and hashes its original observations, assertion outcomes and captured artifact identities. Those facts can be reopened independently of current dispatch authority.

## Decision

Read only the exact acceptance-plan/case/key receipt and require its fixed Docker host kind/version/capability, closed case result and original immutable artifacts. Match the original effect key, plan basis, exact invocation/bindings input digest, applied closed observation, resource revision, provenance and complete observation/assertion/capture hash. Reopen every capture's actual content digest/size and require the exact ordered artifact vector and assertion evidence references. Require the original environment's run, basis, recipe, grant and candidate bindings as well.

A copied host label, substituted artifact, changed assertion outcome or mismatched effect cannot replace original observation proof. The function dispatches nothing and changes no journal. It supports historical reads, including after environment retirement, without claiming current acceptance. Embedded execution/process metadata still needs its separate actual native ownership audit; return nativeOwnership and currentAcceptance as not-established. Whole-product/current-candidate approval must additionally join the exact current assembly, original scopes and original deadlines.

## Alternatives rejected

Trusting a host name or passing flag accepts unsupported claims. Trusting only a content-addressed blob proves its bytes, not which original test produced them. Replaying to recover evidence repeats effects and consumes budget. Treating historical assertion proof as native closure or current acceptance silently broadens its scope.
