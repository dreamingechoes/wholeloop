# 0110 — Owned assembly and complete milestone verification

- **Status:** Accepted
- **Date:** 2026-10-25

## Context

A read-only candidate can describe a manually assembled branch without proving that the controller assembled it. Independently green components can disagree about their shared protocol. Retrying a lost merge, resetting a worker or treating one repository's result as an atomic feature would destroy evidence or exceed the approved scope.

## Decision

1. Prepare immutable assembly records in the external store under the current original private plan grant. Require workspace creation and Git commit scope for every selected repository. Derived envelope plans need the controller's actual plan-acceptance observer; the standalone CLI uses explicit plan grants. Bind the complete observed committed predecessor closure and original base vector. Allocate separate owned worktrees and flat digest-bound topic names beneath the authorized prefix; a preexisting integration branch must not collide with a generated namespace.
2. Create worktrees first, then merge committed parts in global approved dependency-wave order across repositories. Journal each creation and merge as its own original finite effect, with exact expected head and input identity. Disable hooks, signing, prompts and submodule recursion; refuse configured controller-side helpers. Application/test code executes through the existing isolated environment hosts, never as a controller Git hook or filter.
3. Reuse the fixed native wrapper's private registration, cancellation, actual process group and drained-output behavior. Preserve the old environment outcome wire format; give integration its own closed outcome identity. Record ownership before sending command bytes. Observe issued operations instead of invoking them again. Reconciliation can read already-issued effects after revocation/supersession, without restoring authority or dispatching a command. Signal only through the live wrapper's private channel, never a stored PID.
4. Preserve conflict edits and all failed/partial resources. A nonzero Git exit does not imply unchanged files or a rollback. Distinguish observed unmerged entries from ordinary Git failures. A repair names its predecessor, uses a fresh owned worktree and consumes the original integration-repair counter. Accepted repairs fence prior assemblies; no branch reset, force-push, automatic conflict resolution or compensating rollback is authorized.
5. Match a current complete candidate to an actually assembled controller record and one owned ready environment covering the entire repository vector. Reuse the pinned pre-builder acceptance definition: contract cases carry the exact approved contract fingerprint, and a machine case names the exact approved milestone procedure in its actions. Run their actual fixed CLI/API/browser/private hosts, preserve relevant failures and original budgets, and reobserve current inputs before dispatch and reporting.
6. Retain complete failed/passed verification reports as existing bounded private artifacts. Report fixture provenance separately. A human criterion stays pending without its original current operator evidence. Milestone behavioral/contract acceptance never implies whole-feature completion, independent review, publication eligibility or atomic delivery across repositories.

## Alternatives rejected

Merging worker branches in place or rebasing them loses original work. Grouping all merges by repository can put cross-repository consumers before their producers. Reissuing an uncertain Git write confuses completion with retry. Passing arbitrary result JSON into an aggregate would turn claims into execution facts. Running only component suites misses protocol disagreement. An unrelated green test cannot stand in for a pinned contract or approved combined procedure.

## Verification

Use actual disposable Git creation, cross-repository ordering, conflicts, repairs, revocation, finite counters and preserved files. Exercise native closed-process evidence and changed receipts. In the Docker evaluation, independently green frontend/backend units fail together, a committed repair invalidates old evidence and the repaired complete vector passes the same unchanged acceptance. Retain reports and observe exact owned retirement. Scope native-client/model, independent Linux Docker-host and hosted publication/protection certification separately.
