# 0163 — Owned private product verification

- **Status:** Accepted
- **Date:** 2026-10-29

## Context

A private evaluator declares an API case but executes an independent container. It cannot inherit ordinary controller HTTP ownership. Root integration must bind the hidden standard, actual evaluator process and existing sensitivity evidence without exposing definitions to application containers or treating a zero process exit as objective success.

An early product failure also exposes a reporting problem: the ordinary acceptance report selects the latest case. A later unexecuted suite can then inherit an earlier unit result with different bindings. That stale result is not part of the integration attempt and prevents honest recovery of its known failed prefix.

## Decision

Extend the fixed root owner selector with evaluator-container for API/evaluator.private-http. Before consuming root inputs, reopen the exact pinned private definition and require the built-in evaluator source. Keep definition creation before builder admission and preserve all original parent/case/run deadlines. Execute through the existing owned environment scope; recover only the invocation-specific private verify container, its original closed operation/PID completion and the matching immutable definition. Metadata recovery does not require executing or rebuilding the evaluator.

Preserve the existing private assertion and sensitivity policy. A failed objective remains failed even when its evaluator process exits zero. A passing regression evaluator without a relevant observed baseline cannot establish root QA. No worker flag, fallback assertion or invented baseline replaces those facts. This extends the private-case boundary of ADR-0162; browser ownership remains separate.

Build integrated machine reports from their exact candidate/assembly/environment/case keys. Consult ordinary acceptance reports for operator notes only; never borrow their latest machine results. Unexecuted cases have unavailable status and empty evidence. Recompute current bindings and private sensitivity from the exact original receipt. Preserve the failed prefix without weakening the original observer: an unresolved intent for a supposedly unexecuted later case still refuses recovery. Ordinary standalone acceptance reporting remains unchanged.

## Alternatives rejected

Classifying every API case as controller HTTP loses evaluator process ownership. Using only process exit accepts failed private objectives. Downgrading missing sensitivity into a pass invents evidence. Accepting stale or latest unit results after a failed prefix mixes attempts. Replaying later cases just to obtain a complete-looking report consumes another allowance and changes the original failure.

## Verification

The six-file Mac owner/integration/private regression passes 45 tests. Actual Docker controls pass nine success checks, ten objective-failure checks with zero evaluator exit and green unit QA, and nine missing-baseline regression checks. They establish exact-attempt unavailable suffixes, refusal of an injected unresolved later intent, identical restoration, paused/retired recovery and exact environment retirement. Complete isolated Linux checks pass 3374 tests in 178 files and all remaining repository checks; the journal records exact snapshots and bundles. Earlier CLI/API and assembly controls and deadlines remain unchanged. Same-user controller filesystems, authenticated models, browser root execution and independent Linux application-host certification remain separate boundaries.
