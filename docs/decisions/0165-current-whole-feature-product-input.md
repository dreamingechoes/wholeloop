# 0165 — Current whole-feature product input

- **Status:** Accepted
- **Date:** 2026-10-29

## Context

Original unit and milestone QA can pass while different assemblies cover different portions of a feature. Acceptance must receive a tested whole product, not the union of passing labels. Independent terminal milestones therefore need a declared integration join before their separate results can become one feature input.

## Decision

Add a fixed read-only feature reader over the same store's original integration adapter. Require every current milestone stage to be completed and reopen its actual product assertions, original report, native closure and current assembly through that adapter. Capture the exact original binding/consumption/report/record, candidate, applied closed assembly effects, native scope and current unit-stage vector before inspection; reopen after awaiting and recheck every captured product synchronously before returning any input. Changed, missing or partial evidence exposes no product.

Require one declared milestone whose dependency closure includes every milestone, work unit and criterion. Its original passing product report supplies the complete assembly. Every declared procedure must also map to a passed case in that same whole-product report, and all milestones must retain the same pre-builder acceptance plan. Independent terminal products without a join remain blocked; the reader neither invents a milestone nor rewrites an accepted plan.

Expose exact candidate, assembly, pinned acceptance plan and report identities only after the complete vector is current. Ready is an input to the separate acceptance decision and endpoint stages, never feature acceptance or publication. Inspection selects no suite, worker, model or Docker command and works with original closed evidence after pause and retirement. Research completion remains a separate route.

## Alternatives rejected

Combining green milestone flags loses original execution and candidate identity. Combining unrelated terminal assemblies can accept incompatibilities that no common product test observed. Reusing a prior procedure result from another assembly leaves whole-feature coverage incomplete. Rebuilding a final join during inspection would mutate state and silently create a new attempt. Inferring acceptance from readiness bypasses the independently authorized decision.
