# 0162 — Owned root product verification

- **Status:** Accepted
- **Date:** 2026-10-29

## Context

Current independent unit QA and an owned assembly establish readiness for product verification. Historical integrated assertions can also be recovered. Neither fact alone proves that a root integration stage executed the combined cases under its original ownership and deadline. Treating either as a passing integration stage would bypass the remaining product QA.

## Decision

Add a fixed internal integration-stage adapter over the same-store current assembly reader. Match the original root request, plan, milestone and invocation before dispatch, require complete current observed unit QA and the exact current candidate/assembly vector, then consume immutable original inputs once. Refuse a prior unowned case intent or a lost consumed binding instead of borrowing or replaying it. Capture the original context, signal, deadline and selection before asynchronous readiness observation, so later reuse of caller objects cannot replace them or renew the execution window.

Run the pinned complete CLI/API coverage through the original owned environment scope and parent-controlled integrated verifier. Persist the exact budgeted report locator. Recover only its original report, case effects and environment bindings; require closed owned native/read operations, each original case within the original deadline, and each CLI process linked to its original invocation's test container and actual operation/PID completion. Match the exact Docker exit against execution metadata while preserving the private wrapper's zero/one exit normalization. Reopen current unit/assembly readiness and candidate inputs after asynchronous inspection, then recheck the unchanged product evidence, locator, scope and original binding before returning a verdict.

Original closed evidence remains inspectable while paused, expired or after exact environment retirement. Expose the environment scope's original header separately so existing observation shapes and digests do not change. Cancellation addresses original scope owners after revocation rather than requiring current dispatch authority. No report locator or ownership proof means unknown, never another execution allowance.

The adapter returns only the root integration-stage verdict. Whole-feature acceptance, browser/private root-stage ownership, cross-stage repairs, environment preparation composition and public route/endpoint/reconciliation commands remain separate technical work. Select native ownership by both kind and capability: process.exec uses an owned container start and http.request uses the controller HTTP scope. An evaluator.private-http case can declare kind api but still needs its separate evaluator ownership. Unsupported browser/private cases refuse before consuming a root binding; the existing standalone domain evaluators remain available.

## Alternatives rejected

[ADR-0163](./0163-owned-private-product-verification.md) subsequently extends the original private-case refusal with exact evaluator-container ownership and unchanged sensitivity requirements. Browser ownership and full-route composition remain separate.

Passing on assembled bytes or unit flags skips product QA. Passing on retained reports alone loses native ownership and current-candidate proof. Selecting a newer case or recreating a missing consumed resource replays uncertain work. Renewing the deadline at product QA erases assembly/preparation time. Changing existing scope observation fields breaks historical digests. Requiring current authority for metadata inspection or cancellation prevents safe recovery after revocation.

## Verification

Run admission and environment-scope regressions. Extend the existing opt-in assembly evaluation with root product-QA modes while preserving the default controls and all original limits. Exercise original unit verification/review, actual assembly, independent product execution, known integrated failure despite green unit QA, actual HTTP/CLI observations, substituted report/owner-deadline refusal, identical restoration, paused recovery and exact environment retirement. Keep all existing byte-tamper checks; in the HTTP mode perform those read-only fault injections after product execution so they do not spend its original execution window. Record actual results before committing; synthetic workers do not establish authenticated model acceptance or independent Linux application-host certification.

All seven original root CLI controls and all seven known-failure controls pass on macOS Node 24; both preserve original unit QA and retire their exact environments. The final HTTP/CLI mode passes eight controls, including report/scope tamper refusal and paused/retired recovery. A fresh-process audit preserves the original proof, refuses a locator changed during asynchronous QA inspection and restores identical evidence without replay or journal changes. The Mac component regression passes 40 tests; final complete isolated Linux checks pass 3374 tests in 178 files and all remaining checks. The journal preserves the initial API-definition refusal and auxiliary import collision.

The captured-context HTTP/CLI evaluation also passes all eight controls. Fifteen final Mac admission/owner contracts distinguish process.exec and http.request from unsupported evaluators, including an evaluator declaring kind api. The final complete Linux snapshot includes that strict owner selection; all original deadlines and case expectations remain unchanged.
