# 0127 — Owned criterion verification rounds

- **Status:** Accepted
- **Date:** 2026-10-26

## Context

A repository suite proves command behavior, while criterion verification requires independent read-only judgments about the approved requirements. The root runner needs both without inventing a legacy human agreement or allowing a model to certify its own execution. Application and native invokers have different original ownership channels; both must be observed closed before a root stage can pass.

## Decision

Add an internal RunnerVerificationStages component using the existing verify round policy, fixed suite executor and owned native verifier/refuter host. Select only the unit's exact approved criteria. Preserve a private machine-review subject, the original round budget, exact current committed candidate and an immutable root invocation binding before execution. Require bounded credential-checked controller metadata before publishing the descriptor. A consumed missing binding cannot acquire a new round or host call.

Execute the original suite first. An observed failure seals the current blocked round without launching model workers. Missing/uncertain suite observations remain unknown and do not authorize verifier work. A positive suite unit is necessary before independent native criterion inspection and refutation. Native workers cannot execute or manufacture the suite. Bind recovery to the same suite selection and gate, and require the original registered command operation and all application/read/native clients positively closed.

Actual composition exposes serial ownership-query overhead consuming a short suite case's original deadline even after its application command exits. Observe the complete resource vector in fresh bounded inspect batches by Docker kind, with at most sixteen IDs per query and the existing output cap. Require exact cardinality, one complete ownership tuple/stamp per resource, unchanged container/volume/network policy and a positively observed owned volume for every mount. Reuse no previous observation. Single-resource mutation checks retain the same identity/policy validation and freshly batch their mounted volumes; repeated mounts of one owned volume share only that current observation. Container creation also observes all mount dependencies in fresh bounded volume batches before recording intent; missing, extra, duplicate or foreign observations prevent creation. This reduces separately owned read processes without relaxing authority, closure or deadlines.

Audit exact submitted native receipts and votes before using the existing quorum and fail-safe policy. Recover only matching original metadata, including a lost final verdict while paused, without selecting another suite, constructing a new native host or resetting any allowance. Refresh the round projection after child suite recovery so a restored submission is not confused with missing evidence. Cancel original application and native channels independently, even after revocation. No human agreement, testing receipt, complete feature acceptance or endpoint is recorded.

This component requires explicitly assigned criteria. Empty contract-only units need their separate mechanical contract verification rather than invented product criteria. Full repair, research, integration, acceptance and public complete-route composition remain technical P6-10 work. The independent code-review stage remains mandatory after verification.

## Alternatives rejected

Treating a green suite as all QA drops requirement checks. Allowing native execution claims replaces observed processes with model prose. Creating human approval events misrepresents machine decisions. Replanning after losing the private descriptor buys another round. Reusing a stale projection after metadata recovery can discard the exact restored result. Killing by stored PID or cancelling all environment work can affect unrelated processes. Increasing deadlines to make an evaluation pass hides actual invocation limits.
