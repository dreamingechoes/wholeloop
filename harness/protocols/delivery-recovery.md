# Delivery recovery

- ⛔ `delivery-checkpoint-inputs` — pin exact run/plan/attempt and bounded input paths/hashes/sizes in immutable manifests before journaling checkpoints. Verify current bytes on recovery; orphan manifests create no state, authority or semantic acceptance.
- ⛔ `delivery-effect-reconciliation` — retain a scoped finite invocation before one trusted-host action, observe its exact result separately and preserve fixture/controller provenance. Never reissue an issued action; absence needs confirmed invoker termination before not-applied. Unknown outcomes block conflicting writes and successful closure; retry only explicitly transient bounded reads.
- ⛔ `delivery-recovery-ownership` — recover or cancel only exact observed assignment/backend/instance/worker identity. A stop return or reused PID cannot prove termination. Retain reservations and previous gates/budgets; unknown ownership pauses or ends none as blocked without asking a human or starting a replacement.
- ⛔ `delivery-stopped-writer-repair` — ordinary commands never steal locks. Explicit digest-bound repair requires observed absence for the unchanged writer record, serializes repairers and retains the original ownership directory/receipt. Signal no PID, delete no evidence and reconstruct no authority; unknown/live/reused ownership refuses.

- ⛔ `delivery-finite-budgets` — preserve original run/attempt deadlines, finite CI/restart/repair counters, unique artifact reservations and repeated-failure limits across recovery and revisions. Unsupported hard usage caps refuse; missing spend stays unknown and fixture observations stay fixtures. Only a new validated typed result resets no-progress; heartbeats and narration cannot. Never refund or extend a hard allowance implicitly.

- ⛔ `delivery-runner-ownership` — retain original private authority, deadlines and exact stage intent before input. Resume only after positive owned closure; never replay unknown work or signal stored PIDs. Consume private foreground bootstrap once, from its registered actual group and exact installed-core bytes. Recover published result/checkpoint locators without re-execution. Keep research and implementation judgments in their selected decision scopes. Fixture routes cannot establish native QA, endpoint completion or publication.
- ⛔ `delivery-public-controller-bundle` — a public run composes domain adapters only in the controller bundle whose digest the installed core embeds. A missing or changed bundle refuses the run before any claim, and the composer adds only routes it fully supports; every native launch still needs its own observed boundary.
- ⛔ `delivery-public-implementation-inputs` — the runtime document may name a `gh` binary and, per plan repository, a store-prepared recipe, a digest-pinned helper image and the declared suite commands. A ref without exactly one recipe command, an unpinned image or any extra field invalidates the document, and none of these entries grants authority; the plan's exact grant still decides what may be touched. A unit's QA environment is provisioned inside its own verification invocation, once per round, before the round is consumed, and a recovered controller reads that original preparation back. The declared suite runs as controller-owned acceptance cases appended to the produced acceptance plan before it is pinned; a produced case may never redefine one. A queued run completes only with an applied effect on its current basis and a current host-observed endpoint.
- ⛔ `delivery-seeded-correction-workspaces` — a correction workspace may start at the previous revision's committed head of the same run and unit only when that head is the old topic's latest applied, host-observed commit, is a commit object descending from the declared base, and the unit has no predecessors; anything else is refused before any Git effect. A correction builder sees only the retained failure, with private evaluator cases reduced to their id and status, and its result is committed by the controller.
- ⛔ `delivery-operator-visibility` — reports are read-only replays with exact next permitted commands; diagnostics come from an allow-list of categories, digests and enumerated states and never include reasons, payloads, prompts, source, provider responses or credentials. Export recovery bundles only on explicit private request; import only after every checksum matches and each repository is rebound, into an inert archive that restores no journal, claim or grant.

The CLI supplies no actual native/backend host automatically. Inspect checkpoints, effects and writer ownership separately; local fixtures do not certify containment, actual QA or operation-specific publication/merge eligibility.
