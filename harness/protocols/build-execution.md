# Build execution

⛔ `build-plan-before-code`: Record a validated builder plan against the prepared workspace snapshot before implementing; unresolved assumptions require a revision-bound human decision.
⛔ `build-current-gates`: Complete a build only with verify and review PASS on the same current workspace bytes after its recorded plan; ad-hoc work runs both gates too.
⛔ `build-repo-guidance`: Resolve and load repository/user build guidance before the builder; ambiguous bindings stop provisioning.

The deterministic core routes scope/slice/part identities, validates agreed ad-hoc
criteria, provisions workspaces and journals plan/evidence. The host supplies tools,
independent workers, actual observations and cancellation. Core scheduling changes
concurrency across guided/staged/parallel pace while preserving gate coverage.

Never weaken criteria, reset a failed budget or infer human testing from green
machine gates. A changed personal checkout is a host violation to preserve and
report, never something to restore silently. Runtime snapshots and receipts remain
outside repositories; no external message, push or pull request belongs to this step.
