# Guard actions

Use the prepared topic workspace and branch for Build commits, passing its returned environment, including WL_SUBJECT, to the builder. Never commit from an unrelated checkout or infer authority from a command's prose.

Keep configured guards and native sandbox/permission checks active. Do not use no-verify, hooksPath overrides or another execution route to evade a denial. Push only through the exact approved, tested publication plan; stop on changed code, unresolved decisions or a mismatched remote.

Install Git fallback hooks only when explicitly requested. Preserve existing hooks and changed configuration; use the returned inspection/manual-chaining action rather than replacing them. Installation does not establish activation: report an observed missing binding and retain the native permission boundary.

Keep runtime files in the external store. Project configuration is a separate explicit settings action. Do not supply approval, authenticated identity or private reasons on another person's behalf.
