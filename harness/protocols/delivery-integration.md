# Delivery integration

⛔ `delivery-fixed-original-domain-dispatch`: dispatch only through installed fixed domain classes from the same store and resolve the kind from the original issued invocation and immutable plan revision. Copy registrations; reject altered contexts, foreign identities, structural hosts and routes without their fixed research, publication or merge adapter, without fallback. Keep original parent bounds and private cancellation after revocation. Registration coverage grants no native runtime availability, human approval, public complete-route execution or endpoint evidence by itself.

⛔ `delivery-public-runner-host`: public run and reconcile use one fixed host whose identity binds the exact native bindings document. Refuse a different document, revoked grant or stopped run before any claim; compose no native adapter without trusted runtime proof, and end routes needing native clients in preflight without a prompt. Cancel only owned groups through private nonces.

⛔ `delivery-research-dispatch-boundary`: fixed dispatch sends a unit's research stage to the fixed worker adapter and report-level research with its local handoff only to the fixed research host. Without that host, refuse the route; refuse supervised report research and integration milestones holding research work before any dispatch; never drop research criteria to finish.

⛔ `delivery-unattended-research-host`: pin one validated research plan of at most eight angles per invocation; query only available angles, examine each load-bearing claim by separate verifiers, and count only host-observed valid results. Crashes, fixtures and over-budget results stay failures or unknowns. Derive the brief from stored entries alone; complete with unknowns only under that policy; require the delegated source decision on the exact brief. Never continue an interrupted invocation, edit files, merge or publish.

⛔ `delivery-recorded-human-decisions`: under permitted intervention, opted-in build-plan and acceptance stages publish the exact subject a person must judge and wait for input, and the plan stage passes only an exact-plan grant; only the operator command records the person's decision for that subject, never a worker, profile or delegated host. None-policy runs never publish or record one. Pass only on an accepted, unchanged subject; a reject stays blocked.

⛔ `delivery-review-reentry-verification`: implementation units end with a re-entry verification after review. Attest only an original verification that still reopens as passed at the exact current head, with no new work; otherwise verify the reviewed head afresh on its own subject and environment, leaving the original run and budget unchanged. Never borrow a verdict for changed bytes or restart corrections from the re-entry. Readiness prefers a passed re-entry.

⛔ `delivery-static-dispatch-preflight`: fixed-dispatch preflight binds the request identity, current plan and exact derived route and reads nothing else. It requires a fixed product input per integration milestone and an adapter per stage, reports a person required for any non-none policy and claims disabled interactive tools only for a fully covered none-policy route. It never invokes an adapter, model, Git or Docker; runtime proof stays per stage.

⛔ `delivery-owned-local-handoff`: local code-ready requires the latest actual acceptance verdict, exact accepted topics and one observed budgeted report from its original owned-core stage. Bind original consumption/runtime/completion time and recheck current acceptance, report bytes and source after asynchronous observation. Missing locators, changed candidates or flags alone expose no current endpoint and buy no replay. Core PIDs are descriptive, never cancellation targets. Do not substitute local delivery for publication/merge, record human approval or select another model to report deterministic facts.

⛔ `delivery-owned-feature-acceptance`: automatic feature acceptance requires complete current original product QA and the active grant's explicit none-policy acceptance delegation. Consume and bind the exact budgeted input before independent judgment; preserve its original deadline/signal and require closed native outcomes inside that window. Recheck product, input, native owners and authority after asynchronous inspection. Rejection stays blocked; missing input stays unknown without replay. Record no human approval or publication; preserve original-nonce cancellation after revocation or lost locators.

⛔ `delivery-whole-feature-product-readiness`: before exposing feature acceptance inputs, reopen every current original integration verdict and require one tested assembly whose declared milestone closure covers all work, criteria and milestones. Every procedure must have passing evidence in that same product report under the same pre-builder definition. Recheck all products after asynchronous inspection; independent green products, partial vectors or changed proof expose no input. Readiness grants no acceptance, publication, replay or new milestone.

⛔ `delivery-current-assembly-qa`: before exposing a combined candidate for product QA, reopen the complete original observed unit-QA vector and require its exact owned assembly, matching run/plan/source/grant/milestone and positively closed Git effects. Recheck the unit vector, assembly and basis after asynchronous observation; missing, changed or partial evidence yields no candidates.

Assembly readiness is an input to whole-product verification. It grants no integration verdict, feature acceptance, root completion or publication. Inspection may reconcile original metadata but never issues checkout, merge, a suite or a worker. Keep paused recovery separate from dispatch authority.

⛔ `delivery-original-docker-assertions`: reopen exact fixed-host case artifacts through their original applied observation/assertion/capture effect hash and environment bindings. A copied host label or substituted result cannot replace that proof. Read-only history grants neither native ownership nor current acceptance; audit those separately before promotion.

⛔ `delivery-original-integrated-observations`: recover machine-only combined reports from their exact original case keys, immutable candidate/assembly, pinned complete coverage and original Docker assertion effects. Validate each bound environment revision through its complete original chain. Recompute status and repair ownership; never borrow a newer passing case, replay work or promote historical proof into current acceptance or native ownership.

⛔ `delivery-original-acceptance-control`: bound case execution, HTTP requests and artifact capture by the captured original parent deadline, signal and live ownership as well as existing case/run limits. Recheck after asynchronous observation before accounting or dispatch; cancellation must stop owned work and retain original receipts. A new case cannot renew the parent window. Keep metadata recovery separate from live execution authority.

⛔ `delivery-owned-root-product-qa`: a root CLI/API integration verdict requires complete current observed unit QA and its exact assembly plus original pinned product cases executed through closed owned scopes at the original deadline. Bind each CLI process to its original invocation's container and operation completion. Recheck current inputs and unchanged original proof after asynchronous inspection. A lost consumed binding/report or unsupported case yields no verdict and no replay; root integration completion grants no feature acceptance.

⛔ `delivery-owned-private-product-qa`: private API cases require their exact evaluator-container owner and immutable pre-builder definition, not controller HTTP ownership. Preserve private assertions and regression sensitivity independently of process exit. Integrated machine reports use exact original case keys; a failed prefix cannot borrow earlier unit results or hide an unresolved later intent. Missing proof stays unestablished without replay, relaxed assertions or another deadline.

⛔ `delivery-owned-browser-product-qa`: claim the original private stdio exec before spawning and register its actual PID before input. Bind scoped browser commands to their exact acceptance invocation and original parent control; recover only their closed native owners. A screenshot or zero MCP exit cannot override failed objectives. Preserve original-nonce cancellation after revocation, metadata-only paused/retired recovery and unknown results for missing proof.

⛔ `delivery-authorized-publication`: publish only the current accepted product, naming machine acceptance as not human testing, and never write `pr.tested` for it. Push the exact head to the owned topic without force, create one marked draft and ready it only when granted; read the remote completely before each step and stop on a foreign tip or PR, duplicates or a changed head. Reconcile lost writes by reading; never merge, edit unowned PRs or retry a write.

⛔ `delivery-revision-bound-ci`: a required check passes only from its trusted issuer at the exact candidate, by its latest attempt, in a complete observation with observed protection. Pending, cancelled, skipped, neutral, missing, stale, spoofed or partial results and an empty required set never become success; unreadable protection or reviews stay unknown. Wait in finite polls within the run deadline and never prompt a person.

⛔ `delivery-bounded-ci-repair`: classify only a trusted failure at the candidate as a code or test failure and never label infrastructure without structured host evidence. Keep PR comments as identified, unadopted data that is never executed. Count pushes from the journal against the initial-plus-one budget; a request outside it, with non-code failures or with current feedback ends blocked and authorizes nothing.
