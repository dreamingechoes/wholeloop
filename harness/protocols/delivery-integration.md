# Delivery integration

⛔ `delivery-current-assembly-qa`: before exposing a combined candidate for product QA, reopen the complete original observed unit-QA vector and require its exact owned assembly, matching run/plan/source/grant/milestone and positively closed Git effects. Recheck the unit vector, assembly and basis after asynchronous observation; missing, changed or partial evidence yields no candidates.

Assembly readiness is an input to whole-product verification. It grants no integration verdict, feature acceptance, root completion or publication. Inspection may reconcile original metadata but never issues checkout, merge, a suite or a worker. Keep paused recovery separate from dispatch authority.

⛔ `delivery-original-docker-assertions`: reopen exact fixed-host case artifacts through their original applied observation/assertion/capture effect hash and environment bindings. A copied host label or substituted result cannot replace that proof. Read-only history grants neither native ownership nor current acceptance; audit those separately before promotion.

⛔ `delivery-original-integrated-observations`: recover machine-only combined reports from their exact original case keys, immutable candidate/assembly, pinned complete coverage and original Docker assertion effects. Validate each bound environment revision through its complete original chain. Recompute status and repair ownership; never borrow a newer passing case, replay work or promote historical proof into current acceptance or native ownership.

⛔ `delivery-original-acceptance-control`: bound case execution, HTTP requests and artifact capture by the captured original parent deadline, signal and live ownership as well as existing case/run limits. Recheck after asynchronous observation before accounting or dispatch; cancellation must stop owned work and retain original receipts. A new case cannot renew the parent window. Keep metadata recovery separate from live execution authority.

⛔ `delivery-owned-root-product-qa`: a root CLI/API integration verdict requires complete current observed unit QA and its exact assembly plus original pinned product cases executed through closed owned scopes at the original deadline. Bind each CLI process to its original invocation's container and operation completion. Recheck current inputs and unchanged original proof after asynchronous inspection. A lost consumed binding/report or unsupported case yields no verdict and no replay; root integration completion grants no feature acceptance.

⛔ `delivery-owned-private-product-qa`: private API cases require their exact evaluator-container owner and immutable pre-builder definition, not controller HTTP ownership. Preserve private assertions and regression sensitivity independently of process exit. Integrated machine reports use exact original case keys; a failed prefix cannot borrow earlier unit results or hide an unresolved later intent. Missing proof stays unestablished without replay, relaxed assertions or another deadline.

⛔ `delivery-owned-browser-product-qa`: claim the original private stdio exec before spawning and register its actual PID before input. Bind scoped browser commands to their exact acceptance invocation and original parent control; recover only their closed native owners. A screenshot or zero MCP exit cannot override failed objectives. Preserve original-nonce cancellation after revocation, metadata-only paused/retired recovery and unknown results for missing proof.
