# Executable spec definition

- ⛔ `spec-testable-definition` — every story has uniquely identified criteria
  with observable wording and a falsifiable test. Core lint rejects the current
  vague-word lexicon; semantic correctness still needs independent critique.
- ⛔ `spec-pinned-measurement` — every metric retains its provider, stored query,
  unit, baseline, target and window. An unknown baseline identifies missing
  evidence, an answerer and a tracking story. No metrics needs an explicit reason.
- ⛔ `spec-human-approval` — a completed spec stops for a person's revision-bound
  approval. Rejection permits correction; an unfinished new draft cannot receive
  the older revision's approval or bypass the downstream stop.

Follow selected repository spec guidance before drafting. Templates can add or
reorder sections; they cannot remove the core definition needed by later steps.
