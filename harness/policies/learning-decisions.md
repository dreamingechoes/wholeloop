# Core-owned learning decisions rules

- ⛔ `learning-closure` — A canonical completed decision closes its scope. An initiative can close only when every scope has a completed learning decision; generic closure and manually closed siblings cannot bypass that requirement.
- ⛔ `learning-scheduled-observations` — schedule each due checkpoint once by subject, launch, source and policy identity; never read or prompt while scheduling. Unknown stays unknown: none-policy observations end completed-with-unknowns only when the contract allows it, otherwise blocked. Machine recommendations name every unknown and counterargument and never change flags, deploy, message, remove code or close work.
- ⛔ `learning-maintenance-proposals` — turn pinned local inspections into proposals with evidence, base, scope, testable criteria and validation, never into code or tracker changes. Deduplicate recurring findings, retain dismissals with their reason, and expire proposals whose evidence changed. Refuse any proposal touching policy, guidance, rubrics, budgets or evaluations; admit recurring work only within an operator envelope's per-run and aggregate limits, each with its own run and grant.
- ⛔ `learning-maintenance-intake` — take every finding from a fresh run of the operator-pinned inspection, never from a supplied file. Admit a proposal at most once, only while its evidence is current, as its own delivery source; admission creates no plan, queue entry or grant, and planning and the exact-plan grant stay with the operator. Write admissions only if no other admission landed meanwhile.
- ⛔ `learning-observation-runs` — execute a scheduled observation only as its own `learning-observation` delivery run whose plan names that exact scheduled, unsettled key; grant reads and a report only. Unattended runs need a current delegated `learning-outcome` decision; any of keep, iterate, kill or unflag may satisfy it, and none of them changes flags, code, messages or deployments.
- ⛔ `learning-observation-host` — read only through the client's MCP connection, and only reads the grant scopes to the observed subject; an unserved or refused read stays unknown. Store the readings before settling once in this run's name; an interrupted read settles nothing. The recommendation comes from the recorded judgment, names the challenger's counterargument and every unknown, and stays a run artifact.
