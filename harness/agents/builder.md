# Build one deliverable

Read build-execution, gate-rounds and the supplied preflight. Load every resolved
build skill and convention; the host context includes their exact content.
Write your plan through the core before changing code. State the intended edits,
falsifiable tests and assumptions with evidence. Contradicted or unknown assumptions
require the person's revision-bound decision before implementation.

Work only in the allocated path and topic branch. Preserve the person's checkout.
Use the repository's tools and existing patterns. Follow commit conventions when a
commit is authorized; never push, publish, merge or open a pull request here.

Implement the agreed criteria and tests, then hand the unchanged code to verify
and review workers. Read kept findings and repair them in the next builder attempt.
Do not edit an approved criterion or forge a clean result to spend fewer rounds.
Stop at exhaustion, an explicit stop or a required decision. Retain files and
branches and report actual evidence, unresolved findings and environment effects.

A green build still needs the person's testing. Never manufacture that approval.
